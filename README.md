# I AM NOMAD — сайт

Сайт туроператора I AM NOMAD: **https://www.iamnomadkg.com**

Сайт статический, сделан на [Astro](https://astro.build) и лежит на Vercel. Основной язык русский (`/`), английская версия — `/en/`. Страниц 35: главная, о нас, туры и страницы туров, I AM NOMAD SHOW, MICE, отзывы, галерея, FAQ, контакты, политика конфиденциальности и 404.

## Для тех, кто ведёт сайт (без программирования)

### Админка: https://www.iamnomadkg.com/admin/

В админке меняются все тексты (RU и EN рядом), фото, туры, контакты, видео, страница SHOW и цены конструктора.

**Как войти.** Нужен аккаунт GitHub с доступом к репозиторию `pezzonovante09/IAmNomad`.

1. Создайте токен доступа на GitHub: **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
   - *Repository access*: Only select repositories → `IAmNomad`.
   - *Permissions → Repository permissions → Contents*: **Read and write**.
   - Срок действия выберите сами. Когда токен истечёт, создайте новый.
2. Откройте `/admin/`, нажмите **Sign In Using Access Token** и вставьте токен.

Браузер запоминает вход. Токен никому не передавайте: он даёт право менять сайт.

**Как публикуются правки.** Кнопка **Save** сразу сохраняет изменение в GitHub (ветка `main`). Через 1–2 минуты Vercel сам пересобирает сайт, и правка появляется на www.iamnomadkg.com. Перед публикацией сборка проверяет контент: если число дней или пунктов в «Настройки → Туры» не совпадает с текстами либо контакты записаны неверно, сборка останавливается, а на сайте остаётся прошлая версия. Все изменения сохраняются в истории GitHub, поэтому любую правку можно откатить.

**Подсказки:**
- **Списки.** Строки, которые начинаются с `•`, выводятся на сайте пунктами списка. Каждый пункт пишите с новой строки.
- **Фото.** Нажмите на поле фото и загрузите файл: он сохранится в `public/uploads/`. Ссылки на картинки с чужих сайтов не покажутся: их блокирует защита сайта (CSP), исключение только `images.unsplash.com`. Старые фото записаны как ID с Unsplash, их можно оставить. У фото два описания, на английском и на русском: их читают поисковики и незрячие посетители.
- **Реквизиты.** Заполните их в «Настройки → Контакты и видео»: название, ИНН, адрес и часы работы появятся в подвале, на странице контактов и в политике конфиденциальности, а карта покажет адрес офиса. Пока поля пустые, на сайте их нет.
- **Отзывы в меню.** Галочка в «Настройки → Контакты и видео». Пока отзывов нет, пункт скрыт, но страница `/reviews/` работает: на неё можно давать прямую ссылку.
- **Видео.** Для YouTube вставьте ссылку вида `https://www.youtube.com/embed/ID`. Если поле пустое, блок с видео не показывается.
- **Туры.** Список туров и их адреса меняет только разработчик. Число пунктов в «Настройки → Туры» показывает, сколько пунктов из текстов тура выводится на странице.

### Заявки с сайта

Каждая заявка из любой формы (заявка, контакты, корпоративная, SHOW) уходит сразу в два места:

1. **Письмо на почту** через [Web3Forms](https://web3forms.com/), на адрес, к которому привязан ключ.
2. **База данных** [Supabase](https://supabase.com/): проект `iamnomad`, таблица `leads`.

Посетитель видит подтверждение сразу после первого успешного ответа, второй запрос завершается сам. Если одно из двух не сработало, заявка всё равно принимается. Ошибку и запасные контакты посетитель видит, только когда не сработали оба; каждый запрос ждёт не дольше 15 секунд. В заявке нужен телефон или почта, в корпоративной форме почта обязательна. Без JavaScript форма уходит прямо в Web3Forms и заявка приходит письмом.

**Оповещения.** Письмо от Web3Forms — единственное оповещение о заявке, Telegram не используется. Поэтому настройте в Gmail фильтр на отправителя `web3forms.com`: не отправлять в спам, помечать важным, показывать в основной вкладке. Если письмо не ушло, заявка останется только в базе; счётчик `lead_sent` с `channel: db` в Vercel Analytics покажет такие случаи.

**Где смотреть заявки.** Войдите на [supabase.com](https://supabase.com/dashboard), откройте проект **iamnomad** → **Table Editor** → **leads**. Новые заявки видно сразу, их можно фильтровать и сортировать.

| Колонка | Что это |
| --- | --- |
| `created_at` | когда пришла |
| `form` | откуда: `lead` — главная, `contact` — контакты и туры, `corporate` — MICE, `show` — I AM NOMAD SHOW |
| `name`, `email`, `phone`, `tour`, `message` | данные клиента |
| `data` | остальные поля: компания, страна, бюджет, даты, число гостей, WhatsApp, тип события, а также откуда пришёл посетитель: `landing` (первая страница), `referrer` (домен источника), `utm_*` (метки рекламы) |
| `page`, `lang` | страница и язык сайта |
| `status` | **меняйте сами**: `new` — новая, `in_progress` — в работе, `done` — закрыта, `cancelled` — отказ, `spam` — спам |
| `notes` | заметки менеджера |

**Безопасность.** Сайт использует публичный ключ, которому можно только добавлять заявки. Прочитать, изменить или удалить заявки через сайт нельзя: это закрыто правилами доступа (RLS). Смотреть заявки можно только в панели Supabase.

**Защита от спама.** С одного адреса база принимает не больше 5 заявок за 10 минут, всего — не больше 100 в час. Лишние заявки в базу не попадают, но письмо на почту всё равно уходит. Сам IP-адрес не хранится, в колонке `ip_hash` лежит только его отпечаток (хеш).

**Чтобы база не засыпала.** Бесплатный Supabase ставит проект на паузу, если за неделю к базе было мало запросов. Поэтому GitHub четыре раза в сутки обращается к базе: вкладка **Actions** → **Supabase keepalive**. Гарантии это не даёт: на паузу не ставятся только платные проекты. Пока база спит, заявки приходят только письмом, а отзывы и вход через Google не работают. Если задача упала, GitHub пришлёт письмо тому, кто последним менял расписание, а проект можно разбудить вручную в панели Supabase (**Resume project**). GitHub сам отключает такие задачи, если в репозитории 60 дней нет коммитов. Правки через админку считаются коммитами.

### Отзывы посетителей

На странице «Отзывы» посетитель входит через Google, ставит оценку (1–5) и пишет текст. Отзыв сохраняется в Supabase (таблица `reviews`) со статусом `pending` и **на сайте не виден**, пока вы его не одобрите. Письмо о новом отзыве отправляет браузер посетителя, поэтому оно может не дойти: раз в неделю смотрите в таблице фильтр `status = pending`.

**Как одобрить отзыв.** [supabase.com](https://supabase.com/dashboard) → проект **iamnomad** → **Table Editor** → **reviews** → у нужной строки измените `status`: `approved` — показывать, `rejected` — отклонить. Новые отзывы появляются на сайте сразу, пересборка не нужна. Поле `notes` — ваши заметки.

**Что видят посетители.** Имя в виде «Имя Ф.» и фото аккаунта Google берутся из данных Google, а не из формы. При модерации смотрите на автора отзыва. Фото показывается только с адресов Google. Один аккаунт — один отзыв.

**Как удалить данные по просьбе человека.** Удалите пользователя в **Authentication → Users**: отзыв удалится вместе с ним. Если удалить только строку в таблице, почта и IP останутся в системе входа.

**Вход через Google** запускается кнопкой «Оставить отзыв»: до нажатия страница к Google не обращается. Во встроенных браузерах Instagram и Facebook вход может не работать, поэтому там сайт советует открыть страницу в Safari или Chrome. Ссылку на отзывы гостям лучше присылать так, чтобы они открывали её в обычном браузере.

**Вход через Google.** Google OAuth Client ID (тип Web) записан в `src/data/site.ts`. Проект — в Google Cloud на iamnomadkgz@gmail.com, опубликован (In production), Authorized JavaScript origins: `https://www.iamnomadkg.com`, `https://iamnomadkg.com`. В Supabase → Authentication → Providers → Google вставлены тот же Client ID и Client Secret. Провайдер **Email** там же должен быть выключен, иначе отзыв можно оставить без Google и с любым именем. Непустая переменная `PUBLIC_GOOGLE_CLIENT_ID` в Vercel заменяет ID из кода. Если ID убрать совсем, форма отзыва пропадёт, «Отзывы» исчезнут из меню и подвала, а страница закроется от поисковиков.

### Аналитика

Подключена [Vercel Web Analytics](https://vercel.com/docs/analytics): посещения, страницы, источники, страны, устройства. Она работает без cookie, а карты Google и вход через Google загружаются только после нажатия, поэтому баннер согласия не нужен. Если подключить Meta Pixel или Google Analytics, баннер понадобится, а политику конфиденциальности надо будет обновить. Смотреть её в панели Vercel: проект `i-am-nomad` → **Analytics**. Если аналитика ещё не включена, там же нажмите **Enable**.

Счётчики на вкладке **Events**: `lead_sent` (заявка принята; `channel`: `both`, `mail` или `db` показывает, какой канал сработал), `lead_failed` (не сработал ни один), `contact_click` (нажатие на WhatsApp, телефон или почту).

### Если что-то сломалось

| Что случилось | Что делать |
| --- | --- |
| Сохранили в админке, а на сайте не появилось | Сборка остановилась. В Vercel → **Deployments** откройте последнюю сборку: проверка контента называет поле, которое надо исправить. Сайт в это время работает на прошлой версии. |
| После правки на сайте что-то не так | Верните прошлое значение в админке. Разработчик может отменить коммит (`git revert`) или нажать **Instant Rollback** в Vercel; после него новые публикации не выходят, пока не нажать **Undo Rollback**. |
| Заявки перестали приходить | Проверьте спам и вкладки Gmail, счётчик в кабинете Web3Forms (на бесплатном тарифе 250 заявок в месяц) и таблицу `leads` в Supabase. |
| На странице отзывов ошибка загрузки | База заснула: Supabase → проект **iamnomad** → **Resume project**. Заявки в это время приходят письмом. |
| Не входит в админку | Истёк токен GitHub: создайте новый по инструкции выше. |

## Для разработчиков

### Запуск

```bash
npm install
npm run dev         # локально: http://localhost:4321, админка — /admin/
npm run build       # сборка в dist/
npm run check       # проверка типов
npm run check:text  # после build: весь текст помещается на всех страницах (320–1920px)
npm run check:content  # тексты совпадают с настройками туров, контакты записаны верно
```

Нужен Node.js 22.12+. Для `check:text` нужен Chromium для Playwright: `npx playwright install chromium`.

При локальном запуске в админке есть кнопка **Work with Local Repository**. Она правит файлы прямо на диске, без GitHub (работает в Chrome/Edge).

### Как устроено

```
src/
  content/            ← весь контент (его правит админка)
    texts/*.json      ← тексты по разделам: { "ru": {…}, "en": {…} }
    site.json         ← контакты, соцсети, видео
    photos.json       ← фото страниц, галерея, аватары
    tours.json        ← структура туров
    show.json         ← медиа и цифры I AM NOMAD SHOW
    studio.json       ← конструктор: регионы, комфорт, цены, моменты
  components/LeadForm.astro ← все формы: отправка в Web3Forms + Supabase
  data/*.ts           ← типизированные обёртки над content/*.json
  i18n/utils.ts       ← загрузка текстов, t(key), localize()
  views/*.astro       ← страницы (маршруты — src/pages/[...path].astro)
  components/*.astro  ← шапка, подвал, логотип, формы, конструктор и т.д.
  styles/global.css   ← цвета, шрифты, сетка, кнопки
public/
  admin/index.html    ← страница админки (Sveltia CMS)
  uploads/            ← файлы, загруженные через админку
supabase/migrations/ ← SQL таблицы заявок, прав доступа и защиты от спама
.github/workflows/   ← supabase-keepalive.yml: «будит» базу четыре раза в сутки
scripts/
  cms-config.mjs      ← генерирует public/admin/config.yml и копирует редактор
  image-variants.mjs  ← уменьшенные WebP-копии фото из uploads для телефонов
  check-content.mjs   ← проверка контента перед сборкой (build останавливается при ошибке)
  check-text-fit.mjs  ← проверка, что текст помещается
```

**Фото для телефонов.** Перед каждым `dev` и `build` `scripts/image-variants.mjs` делает из каждого фото в `public/uploads/` копии шириной 480, 960 и 1440 px и копию во всю ширину в WebP (`public/uploads/_w/`); битый файл пропускается с предупреждением и список `src/data/image-variants.json`. По нему `srcset()` в `src/lib/img.ts` даёт браузеру выбор, и телефон грузит лёгкую копию вместо оригинала. Копии и список в git не хранятся, готовые копии повторно не пересчитываются.

**Тексты.** Ключи в коде записаны с точками (`t('home.hero.line1')`). В JSON точки заменены на `__` (`home__hero__line1`), потому что в админке точка в имени поля означает вложенность. Если ключа нет в текущем языке, берётся русский вариант, а если нет и его — сам ключ.

**Новый текст.** Добавьте ключ в нужный `src/content/texts/<раздел>.json` сразу для `ru` и `en`. Поле в админке появится само: `scripts/cms-config.mjs` строит список полей из JSON перед каждым `dev` и `build`. Новый раздел добавьте в словарь `sections` в том же скрипте, чтобы у него было понятное название.

**Админка** — [Sveltia CMS](https://github.com/sveltia/sveltia-cms), совместима с Decap CMS. Редактор ставится из npm (`@sveltia/cms`) и при сборке копируется в `public/admin/`. Вспомогательные модули редактор сам подгружает с `unpkg.com`. `config.yml` и копия редактора генерируются, в git их нет.

**Логотип** собран из текста и CSS (`src/components/Logo.astro`): «I AM» — `#E4AE25`, «NOMAD» — `#07703F`, «O» — кольцо с золотой точкой. Иконки сайта (`public/favicon.svg`, PNG) используют этот же знак.

### Переменные окружения

Задаются в настройках Vercel, см. `.env.example`:

- ключ Web3Forms задан в `src/data/site.ts` (привязан к почте компании);
- `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_KEY` — проект Supabase и его публичный ключ для записи заявок (по умолчанию проект `iamnomad`, см. `src/data/site.ts`);
- `PUBLIC_GOOGLE_CLIENT_ID` — заменяет Google OAuth Client ID из `src/data/site.ts` (для входа в форме отзывов);
- `SITE_URL` — адрес сайта для canonical, hreflang, sitemap и превью в соцсетях (по умолчанию `https://www.iamnomadkg.com`).

### Публикация

Каждый push в `main` Vercel сам собирает и публикует на www.iamnomadkg.com; iamnomadkg.com перенаправляет на www. Для других веток Vercel делает preview-сборки. Старые адреса (`tour-classic.html` и т.п.) перенаправляются на новые через `vercel.json`.

**Защита.** В `vercel.json` заданы заголовки безопасности. CSP на публичных страницах разрешает только перечисленные адреса: если подключаете новый внешний сервис (скрипт, карту, видео), добавьте его туда, иначе браузер его заблокирует. На `/admin/` CSP пока в режиме Report-Only: войдите, поработайте, посмотрите консоль браузера и только потом включайте его как обязательный.

### База заявок (Supabase)

Таблица `public.leads` в проекте `iamnomad` (регион eu-central-1). Роли `anon`/`authenticated` могут только вставлять строки и только в колонки `form, name, email, phone, tour, message, data, page, lang`. Колонки `status` и `notes` сайт заполнить не может. Длины полей ограничены проверками в таблице. Форма шлёт `POST /rest/v1/leads` с заголовком `Prefer: return=minimal`, поэтому ответ не содержит данных.

- Частоту ограничивает триггер `private.leads_rate_limit()`: 5 заявок с IP за 10 минут и 100 в час всего. IP берётся из заголовков запроса PostgREST и хранится только как `md5` с солью (`ip_hash`). Сайт записать `ip_hash` не может.
- Функцию `public.keepalive()` и чтение из таблицы `reviews` раз в 6 часов выполняет `.github/workflows/supabase-keepalive.yml`, чтобы бесплатный проект не уходил на паузу.
- SQL всех изменений лежит в `supabase/migrations/`. Все файлы, кроме `20261105120000_audit_hardening.sql`, в проекте применены, повторно запускать их не нужно.
- `20261105120000_audit_hardening.sql` подготовлен, но **не применён**: убирает Telegram (включая токен бота и `pg_net`), переводит отпечаток IP на HMAC с очисткой через сутки, смягчает общий лимит заявок и берёт имя и фото отзыва из `auth.identities`. Перед применением прочитайте файл и проверьте заявку и отзыв на проде.

### SEO

- `sitemap-index.xml` с RU/EN версиями (`@astrojs/sitemap`), `robots.txt` (`/admin/` закрыт);
- canonical, hreflang и Open Graph на каждой странице;
- страница 404 и админка закрыты от индексации.
